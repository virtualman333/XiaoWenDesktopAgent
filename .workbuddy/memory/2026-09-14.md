# 2026-09-14 工作日志

## v1.0.4：语音识别改造 + 修复对话 HTTP 400

### 1. 语音识别方案替换（核心）

**问题**：语音输入完全不可用，永远报 `network` 错误。
**根因**：原实现用 Chromium 内置 `webkitSpeechRecognition`，该能力由 Google 云端提供，
国内网络必然不可达。属于技术选型错误，不是网络抖动。
**方案**：改用阿里云百炼 paraformer-realtime（WebSocket 实时流式识别）。用户已提供
DashScope API Key 并写入 `config.json` 的 `asrApiKey`。

**实现**：
- 主进程新增 `asr:start` / `asr:audio` / `asr:stop` / `asr:cancel` / `asr:test`
- 渲染进程 `speech.js` 重写：`getUserMedia` + AudioWorklet（降级 ScriptProcessor）
  采集 16kHz 单声道 PCM，重采样转 Int16，按 100ms 分片发给主进程
- 音频以**二进制帧**发送，不做 base64
- 静音超过 `asrSilenceMs`（默认 2s）自动结束并发送
- 设置页新增：识别方式选择、百炼 API Key、模型名、静音时长、测试按钮
- 系统内置识别保留为 `provider='system'` 备选

### 2. ⚠️ 关键坑：Electron 主进程没有 WebSocket

**这是本次最容易踩、且我已经踩过的坑**：

| 环境 | Node 版本 | 全局 WebSocket |
|---|---|---|
| 系统 Node 22 | 22.22 | ✅ 有 |
| Electron 32 内置 | **20.18.1** | ❌ **undefined** |

全局 `WebSocket` 到 Node 22 才默认可用。用系统 Node 做协议验证会通过，
但**在 Electron 主进程里必然失败**。必须 `npm i ws`。

另外 `ws` 与浏览器实现的**回调签名不同**：
- `ws`：`onmessage = (data, isBinary)`，data 直接是内容
- 浏览器：`onmessage = (event)`，内容在 `event.data`

已写兼容层 `readTextFrame()` 统一处理。发送音频时显式转 Buffer +
`{ binary: true }`，确保走二进制帧。

### 3. 修复对话 HTTP 400

**错误信息**：`ai is not one of ['system','assistant','user','tool','function']`
**根因**：界面内部一直用 `'ai'` 作角色名（气泡 CSS 类名、历史记录），
发请求时没转成 `'assistant'`。
**修复**：
- `panel.js` 新增 `normalizeRole()`，渲染层构造 payload 时归一化
- `main.js` 发请求前再做一层归一化兜底（防老历史数据）
- `messages` 数组统一存 `'assistant'`，UI 类名仍用 `'ai'`
- 清洗了 config.json 历史里 1 条 `'ai'` 记录

**验证**：role=ai → HTTP 400（与用户报错一致），role=assistant → HTTP 200。

### 4. 环境坑（持续有效）

- **bash 缺 coreutils**：`ls` / `wc` / `dirname` / `tail` 全部 not found。
  一律用 Python 执行 shell 命令。
- **`ELECTRON_RUN_AS_NODE=1` 泄漏**：当前工具环境设了这个变量，导致用
  `electron.exe` 启动应用时 `require('electron')` 返回**字符串**（exe 路径），
  `app` 为 undefined → 启动即崩。启动 Electron 前必须从 env 里删掉它。
- **`app.getPath('userData')` 在独立脚本里是 `AppData\Roaming\Electron`**，
  不是 `xiaowen-assistant`。诊断脚本要显式 `app.setPath('userData', ...)`。
- **tasklist 输出是 GBK**，Python 读要 `decode('gbk')`，否则 UnicodeDecodeError。
- **Bash 调用结束会杀掉整个进程树**，所以无法用「后台启动 + 后续连接 CDP」
  的方式验证 Electron。改为**一次性脚本**：启动→验证→输出→exit，同一进程内跑完。
- **诊断脚本要加 `--disable-gpu --no-sandbox`**，否则 GPU 进程反复崩溃会连带
  终止主进程（FATAL: GPU process isn't usable. Goodbye.）。
- 沙箱会拦截目录删除（safe-delete），打包目录被占用时改输出到新目录。
