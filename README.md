# 小问助手 · 桌面 AI 智能体

常驻屏幕右下角的「软件贾维斯」：能听、能说、能记住你，还能**真正操作你的电脑**。

## 功能一览

| 功能 | 说明 |
|---|---|
| 🧩 **工作台界面** | 不是一问一答的聊天页：**一张卡 = 一件事**（原话 + 执行轨迹 + 结论 + 下一步动作），配合 `Ctrl+K` 命令面板和输入框下的意图预览 |
| 🗣️ **语音唤醒** | 说「小问」即可免按键唤起，不用碰鼠标键盘（默认关闭，需在设置里开启） |
| 🐧 **桌面宠物** | 6 只手绘动物（企鹅/橘猫/熊猫/兔子/柴犬/青蛙）任选：点击互动、拖拽、喂食、睡觉、散步、升级养成，小问回答时它帮你播报；**开着宠物就会自动顶替悬浮球**（见下一行） |
| 🎈 **桌面入口二选一** | 悬浮球和宠物是同一个入口的两种样子，同一时刻只出现一个：宠物开着悬浮球自动退场（单击聊天 / 双击语音 / 右键菜单 / 语音唤醒全由宠物接管），宠物关掉悬浮球自动回来 —— 桌面上永远留一个能点的东西 |
| 🎭 **宠物联动** | 小问思考/调工具/完成/失败时，宠物头顶亮徽标、原地小跑、蹦一下或摇头 |
| 🤖 **Agent 模式** | 小问可自主调用工具多步操作：执行命令、读写文件、截屏、管进程、开应用 |
| 🧑‍💼 **子代理编排** | 常任务自动拆成子任务派给子代理，派完就告诉你；子代理拿不准会回头请示，**小问优先决策**；小问全程监督、验收、失败改派重试，最后只汇报结果 |
| ⏰ **定时任务** | 定好时间让小问自动干活（只跑一次 / 每天 / 每周 / 每月 / 每隔 N 分钟），到点**主动来找你**；小问自己也能建任务；支持中文写法「每天 08:30」「每 2 小时」「晚上 8 点」 |
| 🧠 **动态上下文** | 长会话自动按预算压缩：截断超长工具输出 → 保留最近 N 轮 → 更早的折叠成纪要 → 还超就丢最旧的；输入框旁的**上下文环**随时能看到用了多少 |
| ⚡ **异步调度 · 先反馈再给结果** | 任务不阻塞界面：立刻显示「运行中」，6 秒还没跑完才补一句「收到，这就去办」，结论一条到位；并发池（默认 2）超出排队 |
| 🔔 **主动关注** | 地震（USGS）、百度/微博热搜、关键词新闻主动盯着，有新情况第一时间推给你 |
| 📋 **剪贴板感知** | 复制一段报错 / 代码 / 链接后，小问主动问一句「这段要我看看吗」：宠物动一下 + 托盘气泡 + 一条可点通知，点一下面板就出来、**问法已经按内容类型写好**（报错 / 代码 / JSON / 链接 / 长文各一套），可直接回车也可改。默认关闭（常驻读剪贴板属隐私敏感行为）；**疑似 API Key / token / 密码一律不提示**（这条没有开关），免得密钥被印在通知横幅上。**识别规则可自己加**：公司日志前缀、内部域名、自家框架的栈帧格式都能配进 `clipSenseRules`，改完立即生效；在**设置 → 📋 剪贴板感知**里直接改，带实时校验与生效结果预览，规则可导出 / 导入（换机器不用手抄 JSON） |
| 🎙️ **会议自动记录** | 自己发现你在开会 / 视频 / 语音通话（看谁占着麦克风摄像头 + 窗口标题），一边听一边转文字，结束后给一份带**要点和待办**的纪要；不想录就一句话关掉 |
| 🖼️ **截图问答** | `Alt+Shift+A` 框选 / `Alt+Shift+S` 整屏（快捷键可在设置里录制修改），截完自动带到对话框，直接问小问「这报错啥意思」 |
| 🔄 **静默升级** | 后台下载不打断你；可以等电脑空闲（默认 90 秒）再静默安装重启，也可以点一下立刻装 |
| 🔌 **MCP 支持** | 接入 MCP 服务器生态（stdio / http），无限扩展工具 |
| 📦 **Skills 技能** | 用 SKILL.md 给小写「工作手册」，按需加载 |
| 🧠 **记忆** | 长期记忆（自动检索注入）+ 短期记忆（多会话管理）。在**设置 → 🧠 记忆**里可以**当场试一句话**，看它会让小问想起哪几条 —— 与对话注入走**同一套检索、同一个条数**，所以这里没命中就是对话里也不会想起；调不出记忆时先看这里 |
| 👤 **人格** | 它知道自己是谁、主人是谁；名字、性格、说话风格都可定制 |
| 🔊 **语音输出三方案** | 系统内置（离线）/ 阿里云 CosyVoice（高音质）/ OpenAI 兼容 TTS |
| 🎙️ 语音识别 | 阿里云百炼 paraformer-realtime 实时流式识别 |
| 🚀 **开机自启** | 登录系统自动在托盘运行 |
| 右下角悬浮球 | 始终置顶，可拖动、自动吸附边缘、透明度调节 |
| 全局快捷键 | 默认 `Alt+Space`，任意界面语音提问 |

## 快速开始

### 方式一：直接运行安装包（推荐）

1. 双击 `release-v1.2.0/` 下的 `小问助手 Setup.exe` 安装
2. 安装完成后从桌面或开始菜单启动
3. 右下角会出现蓝色悬浮球，**首次启动会自动弹出配置引导**：选服务商 → 填 API Key → 测连通 → 完成
   （如果跳过了引导，也可以右键托盘图标 → **设置** → 填入你的 API Key）
4. 开始使用

### 方式二：从源码运行（开发）

```bash
# 1. 安装依赖
npm install

# 2. 构建界面
npm run build:renderer

# 3. 启动
npm start
```

首次启动会自动打开面板并弹出「首次配置引导」，按提示 30 秒即可配好。
想重新走一遍：设置 → 常规 → **重新运行首次配置引导**。

### 密钥安全（重要）

- 本项目是**公开仓库**，任何真实 Key 一旦 commit 进 git 历史都视为已泄露，请立刻去服务商控制台轮换
- 本地密钥建议走环境变量：把 `.env.example` 复制为 `.env` 填入（`build/_jarvis_e2e.js` 会读 `DASHSCOPE_API_KEY`）
- `config.json` 与 `.env` 都已在 `.gitignore` 中，不会被提交
- 应用运行时，密钥只保存在本机 `%APPDATA%\xiaowen-assistant\config.json`，渲染进程拿到的始终是打码值

### 剪贴板感知的识别规则

**最省事的改法**：设置 → 📋 剪贴板感知。里面有开关、规则编辑框、以及一块**实时生效结果** —— 边打字边告诉你「仍然提示哪些类型、哪几条规则被丢掉了、识别到几个自定义类型」，写错字段名会点名报警。保存前必过校验，写岔了根本存不进去。

同一页还有**「拿一段内容试试」**：贴一段内容（或一键取用当前剪贴板），立刻看到它**会不会被提示、判成了哪一类、为什么不会提示**，以及复制后会自动填进输入框的完整问法。**不必先保存规则就能试**，随时试、只读不落盘。

规则还能**导出 / 导入**（「导出到文件」/「从文件导入」）：导出的是输入框里当前这一份（含还没保存的编辑，导出前先过一遍校验），默认文件名带日期便于留档；导入只把文本读进输入框、**不自动保存** —— 看过摘要确认无误后再点「保存规则」才生效，免得换机器时导进来一份不对的规则直接盖掉原来的。

这块是给「规则写对了却毫无反应」准备的 —— 那种情况下不提示的原因有五种，光看规则根本分不出来：

| 试跑会告诉你 | 对应你要做的事 |
|---|---|
| 内容太短（门槛 12 字符） | 什么都不用改，这是有意的 |
| 疑似凭证 —— 硬保护 | 什么都不用改，凭证识别没有开关 |
| 命中「永不提示」正则（并指出是哪一条） | 改 / 删那条 `ignorePatterns` |
| 命中的内置类型被关掉了（并指出是哪一类） | 从 `disableKinds` 里去掉它 |
| 认不出类型 | 这才是真的该写 `customKinds` |

想直接手改配置也行。内置 5 类（报错 / 代码 / JSON / 链接 / 长文本）认不出你自己的世界 —— 公司内部日志前缀、内部域名、自家框架的栈帧格式。这些配在 `config.json` 的 `clipSenseRules`（改完立即生效，不必重启）：

```json
{
  "clipSenseEnabled": true,
  "clipSenseRules": {
    "disableKinds": ["url"],
    "ignorePatterns": ["^\\[内部\\]"],
    "customKinds": [
      { "id": "corp-log", "label": "公司日志", "pattern": "^\\[corp\\]", "flags": "im",
        "title": "这段公司日志要我看看吗？", "ask": "帮我分析这段公司日志。" }
    ]
  }
}
```

| 字段 | 作用 |
|---|---|
| `disableKinds` | 关掉不想被提示的内置类型，只能填 `error` / `json` / `url` / `code` / `longtext` |
| `ignorePatterns` | 永不提示（正则），命中即静默，优先于 `customKinds` |
| `customKinds[].pattern` / `flags` | 你自己写的正则；`flags` 默认空，常用 `i` / `m` |
| `customKinds[].ask` / `title` | 这一类的问法与通知标题；不填则按 `label` 生成兜底说法 |

判定顺序：**凭证 → `ignorePatterns` → `customKinds` → 内置 5 类**。这是先到先得的硬顺序，所以自定义规则不生效时，先用上面那块「拿一段内容试试」看是不是**前面某条先命中了** —— 界面会直接告诉你是哪一条。

字段名写错（`ignorePattern` 这种）会得到一条**点名到字段**的警告，界面与日志里都能看到：规则知识只有 `src/main/clip-sense.js` 一份，设置界面走主进程的 `parseRulesText` 校验、试跑走主进程的 `testRules`，不自己实现一遍（连内置类型的显示名都由主进程下发，界面不留第二份）。

**凭证识别没有开关**：`disableKinds: ["secret"]` 会被当作未知类型拒绝，`customKinds` 的 `id` 也不能占用 `secret` / `ignore` / 内置类型名。误报一次，密钥就印在系统通知横幅上了，收不回来 —— 这条捷径不开放。

正则写岔（编译不过、超长、`flags` 非法、缺 `id`、`id` 重复）只记一条日志警告并跳过该条，不影响其它规则也不影响轮询；`g` / `y` 标志会被自动去掉（带 `g` 的正则 `test()` 有 `lastIndex` 状态，会让同一段内容时提示时不提示）。

## 使用方式

### 文字问答
- 单击悬浮球 → 打开面板 → 输入问题 → `Enter` 发送
- `Shift+Enter` 换行

### 语音问答
- **双击悬浮球**，或按 **`Alt+Space`**
- 对着麦克风说话，说完停顿一下自动发送
- AI 回答会自动朗读（可在面板底部取消勾选「朗读回答」）

### 桌面入口：宠物 或 悬浮球，二选一

**这两个是同一个入口的两种样子**，功能完全重叠，所以同一时刻只出现一个：

| 宠物 | 悬浮球的设置 | 桌面上是谁 |
|---|---|---|
| 开着 | 自动（默认） | **宠物**（它完全代替悬浮球） |
| 开着 | 总是显示 | 两个都在 |
| 开着 | 不显示 | 宠物 |
| 关着 | 任意 | **悬浮球** |

宠物关掉时悬浮球一定会回来 —— **桌面上不会两个入口都没有**。
想两个都留着：设置 → 通用 → 悬浮球 → 「总是显示」；或者 Ctrl+K 里搜「换个班」。

## 工作台界面（v1.7 新增）

主界面刻意**不是**一问一答的聊天页 —— 它更像一条「事情的时间线」：

- **一张卡 = 一件事**。卡头是你的原话 + 状态 + 时间；中间是**可折叠的执行轨迹**
  （调了什么工具、成没成）；下面是结论；卡脚是下一步：
  复制 / 朗读 / 重答 / **⏰ 定成定时任务** / **🧩 派给子代理** / **🧠 记进记忆**。
  同一件事的回执和结果只改写同一张卡，不刷屏。
- **意图预览**：边打字边告诉你「这件事会怎么干」；命中「每天 / 提醒我 / 早报」这类长期动作时，
  直接把 **「就这么办」** 按钮递过来，一键排成定时任务。
- **`Ctrl+K`** 打开命令面板，模糊搜命令；没匹配就把输入的那句话直接交给小问。
- 主动播报（热搜、地震、定时任务结果）也混在这条时间线上，只是换个图标和来源标签。

## 上下文自动压缩（v1.7 新增）

长对话不会再把模型卡爆。每一轮按预算裁剪，全程不用你操心：

1. **截断超长工具输出** —— 保留「头 + 关键行 + 尾」。上千行的构建日志里那条报错常常卡在正中间，
   所以额外把 `error / failed / 异常 / 超时` 这类行捞出来带上。
2. **最近 N 轮保留原文**（默认 8 轮）。
3. **更早的对话折叠成纪要**（`【更早的对话纪要】`），并且会异步让模型写一份滚动摘要存进会话。
4. 还超预算就整轮丢弃（带保护，不会清空上下文）。

输入框右下角的**上下文环**常显用量，压缩过会亮「压」角标，悬停能看到压缩前后、
截断了几条工具输出、折叠成几行纪要。相关设置项：
`ctxWindow` / `ctxReplyReserve` / `ctxKeepTurns` / `ctxAutoCompress` / `ctxToolOutputMax`。

## 任务调度：先反馈，再给结果（v1.7 优化）

很多任务是异步的，界面不该傻等：

- 任务一开跑**立刻**发 start 事件，面板上秒变「运行中」；
  **6 秒还没跑完**才补一句「收到，这就去办」——跑得快就一条结论到位，不会被两条横幅连着打扰。
- 结论**一定**会投递；超 45 秒再补一句「还在办」。
- 并发池默认同时跑 2 个（设置 → 定时任务里可调 1–4），超出排队；同一任务重复触发只跑一份。

### 排队这件事看得见（v1.13 起）

并发满了，其余任务会在队列里等 —— 而在这之前，「排队」在界面上是完全隐形的：
点了「跑一次」没反应，只能怀疑是不是坏了。现在设置页的**定时任务**顶部有一块调度概览：

| 显示什么 | 为什么值得占这块位置 |
|---|---|
| 启用任务 / 运行中 / 排队 / 并发上限 / 调度开关 | 五个数字一眼看完，不用猜「我刚点的那个跑了吗」 |
| 接下来 5 次分别几点跑 | 排了「每 30 分钟」的任务，能直接看到下几次是几点 |
| 最近 20 条运行记录 | 失败标红、排过队的注明「（排过队）」——「这次为什么慢」有据可查 |

单个任务那一行会挂上「排队中」、按钮变成「已排队」；正在跑的任务即使重开面板也不会漏
（面板自己那份「谁在跑」是空的，现在以主进程为准 —— 此前重载后会把在跑的任务显示成空闲，
「跑一次」按钮也重新可点）。

队列的几条规矩：

- 同一任务重复触发**只排一份** —— 并发满时连点两下「跑一次」，不会排进去两条、事后跑两遍
- 排队期间被**删除 / 暂停**的任务会立刻出队，不会再被跑出来，也不会再播报一次
- 退出时排队中的任务一律作废（不跨重启：隔了一次重启才冒出来的旧结果没有意义）

## 子代理编排（v1.5 新增）

遇到「步骤多、要跑一会儿」的常任务，小问不再一步步问你，而是自己当主管：

```
主人：帮我把下载目录里所有 PDF 按月份整理好，再出一份清单
  │
  ├─ 小问判断：这是常任务 → 拆成 3 个子任务
  ├─ 派活（对话里立刻告诉你派了什么）+ 任务看板实时显示进度
  │     ├─ 子代理 A：扫描下载目录里的 PDF
  │     ├─ 子代理 B：按月份归类（并行）
  │     └─ 子代理 C：生成清单
  ├─ 子代理拿不准 → ask_supervisor 请示 → 小问直接拍板（不打扰你）
  ├─ 每个子任务交回来，小问复核：不过就改派重试（默认重试 1 次）
  └─ 全部收工 → 小问汇总成一段话汇报
```

**规则**：
- **小问只管派活和监督**：拆任务、派活、验收、重试、汇报，具体执行交给子代理
- **派完就告诉你**：对话流里会写明拆了几个任务、分别是什么，宠物也会同步演出
- **小问优先决策**：子代理遇到歧义请示小问，小问直接给决定（并记在看板上），不会反过来打断你
- 拆不拆由小问判断，也可以在设置里改成只在你明确要求时才分派
- 子代理没有 `delegate_task`（防止无限套娃），单个任务最多请示 3 次

设置位置：**设置 → Agent 能力 → 子代理编排**。

## 会议自动记录（v1.8 新增）

开会时最烦的两件事：一是没人记纪要，二是记完还得自己整理。
小问现在会**自己发现你在开会**，一边听一边转成文字，结束后给你一份带要点和待办的纪要。

### 它怎么知道你在开会

Windows 没有「现在在开会吗」这种接口，所以小问靠三个客观信号凑：

| 信号 | 怎么读 | 说明 |
|---|---|---|
| 麦克风 / 摄像头占用 | 注册表 `CapabilityAccessManager\ConsentStore` | 最硬：`LastUsedTimeStop = 0` 就是「还在用」 |
| 进程列表 | `tasklist /v` | 把「谁在用麦」翻译成人话，也认浏览器里的网页会议 |
| 窗口标题 | 同上 | 「语音通话」「正在共享」「Google Meet」这类关键词 |

光看标题会误报 —— 腾讯会议、钉钉、飞书都爱开机常驻、窗口一直开着，
所以**标题必须配合「麦克风真的被占用」才算数**。另外还有两道过滤：
**小问自己用麦克风不算**（语音问答也占麦，不排除就会「一问就以为在开会」）、
**进程已退出的注册表残留不算**。

开关只管自己那一路：**麦克风信号没有开关**（它是主判据，一直在采），
「摄像头被占用也算在开会」只决定要不要多读一路摄像头。
设置页那个「同时采集麦克风」是**录音**参数，跟检测无关 ——
三个开关里只有它管录制，另两个管检测。
「检测我现在是不是在开会」会先说清这一轮探了哪几路信号，不用靠猜。

判定用**迟滞**：连续采到 N 次（默认 2 次 × 5 秒）才算开始，连续 90 秒采不到才算结束。
宁可晚几秒开始，也别一开机就误报。

### 记什么、怎么记

- **采集系统声音（Windows loopback）+ 麦克风**：会议里对方的声音是从扬声器出来的，
  只有 loopback 能录到，且不用装虚拟声卡；自己的发言直接采麦。两路音频求和成一路
  16kHz 单声道 PCM 送识别。
- **长会议会自己换连接**：每 5 分钟主动轮换一条识别会话，换的期间音频先排队、
  新会话起来立刻补发，不丢话。
- **转写会清洗**：丢掉「嗯嗯嗯」这类噪声，合并反复吐出来的重复句。
- 结束后生成结构化纪要：**主题 / 要点 / 结论 / 待办 / 风险与疑问**，
  存成 Markdown + 一份含全文转写的 JSON，放在「设置 → 会议纪要 → 打开纪要文件夹」里。
- **三道自动收尾**：连续 5 分钟没人说话 / 到达单次上限（默认 120 分钟）/
  程序退出前同步落盘。

### 隐私

- 检测到会议后**先播报一句再开始录**，绝不偷偷录。
- 可以改成「开始前先问我一句」，也可以关掉自动记录只留提醒。
- 音频只在你本机与**你自己配置的**语音识别服务之间流转，不经过小问的任何服务器；
  文字纪要存在本机 `userData/minutes/` 下。

### 怎么用

| 入口 | 操作 |
|---|---|
| 自动 | 什么都不用做，检测到就记，结束后主动把纪要送给你 |
| 命令面板 | `Ctrl+K` → 「开始记录会议纪要」/「结束记录并生成纪要」/「检测我现在是不是在开会」 |
| 设置页 | 设置 → **🎙 会议纪要**：开关、灵敏度、静默时长、单次上限、是否录麦 |
| 看一份纪要写了什么 | 「最近的纪要」里点那一行的 **看** → 主题 / 要点 / 结论 / 待办 / 风险与疑问 / 全文转写直接在窗口里展开，不用离开小问去开文件（再点一次收起） |
| 看录制进度 | 录制中点 **看当前转写** → 拉取这一段到目前为止的完整转写与字数；不点开就不占地方 |
| 对着小问说 | 「开始记录会议」「刚才那个会记了什么」「找找提到排期的会议」 |
| 排障 | 设置页里「现在是什么状态」+「立即检测一次」会把判定结论和理由直接摊出来；命令行里还能跑 `npm run probe:meeting`（真读注册表 + 真列进程，把「谁在用麦、为什么判成 / 没判成在开会」全打出来） |

> 需要先在「设置 → 语音」配好语音识别 Key，否则只能检测不能记录（会提醒你去配）。

### 找不到宠物了？（v1.6 + v1.7 修复）

两次不同的原因：

1. **v1.6 修的** —— 透明窗口在 Windows 上被 `setPosition()` 一次撑高 1px，散步时每秒十几次，
   窗口很快长到屏幕外。已从根上修掉（移动改成带尺寸的 `setBounds`）。
2. **v1.7 修的（这次的真相）** —— `alwaysOnTop` 只是把窗口放进「最上层那一组」，
   **组内顺序取决于最后激活时间**：任何后创建的置顶窗口（会议共享画面、全屏播放器、
   悬浮歌词、下载弹窗）都能把宠物**永久**盖住，看起来就像「宠物没显示」。

v1.7 的加固：

- 宠物改用 `setAlwaysOnTop(true, 'screen-saver')`（比普通置顶高一级，普通 `alwaysOnTop`
  窗口已经盖不住它），被压住时用 `moveTop()` 重夺最上层，另有 **30 秒一次的兜底重夺**。
- 连续两次判定「不可见」或窗口整个不存在 → **直接销毁重建**；
  显示器插拔 / 休眠唤醒造成的窗口 surface 过期也会自动重建。
- **`Alt+Ctrl+P` 召唤宠物到鼠标处**（可自定义），托盘右键也有；
  设置 → 🐧 桌面宠物里能开关置顶、开关防遮挡重夺，还有**说人话的诊断**
  （会诚实告诉你「窗口是好的，只是被某个置顶窗口盖住了」或者「它跑到屏幕外了」）。
- 设置 → 🐧 桌面宠物 → **📍 叫回主屏** 一键找回来，托盘右键还有「强制重建宠物窗口」。

## 语音唤醒（v1.3 新增）

> 监听由谁托管是自动切换的：宠物关着 / 悬浮球在场时是悬浮球在听，
> 悬浮球退场（宠物顶替它）时就是**宠物在听**，宠物头顶会亮一只「耳朵」小标。
> 两边不会同时开麦 —— 同时开会互相顶掉对方的识别会话。


开启后，直接说「小问」就能把它叫起来，不用去点悬浮球也不用按快捷键。

**开启方式**：设置 → 语音 → 语音唤醒 → 打开开关（默认关闭）。
开启后悬浮球核心会多一圈青色微光，表示它正在听。

**它是怎么工作的**（两级检测，兼顾灵敏和省钱）：

| 阶段 | 做什么 | 成本 |
|---|---|---|
| ① 本地常驻监听 | 麦克风一直开着，但只算音量判断「有没有人说话」 | 零，不发任何网络请求 |
| ② 云端确认 | 只有检测到人声，才开一次约 2~3 秒的识别，拿文本比对唤醒词 | 一次短识别 |

**几个实现上的取舍，你可能会关心：**

- **没有引入额外 Key 或模型**。专业唤醒方案（Porcupine / sherpa-onnx）要么要再申请一个 Key，要么要下载模型加原生依赖，对这个纯 JS 小工具太重。这里复用了你已经配好的语音识别通道。
- **预缓冲 700ms**。人是先说出「小问」、VAD 才反应过来的，等连上识别服务，第一个字早过去了。所以引擎会环形保留最近 700ms 的音频，会话一建立就补发过去，唤醒词不会被截断。
- **同音字放宽**。中文识别经常把「小问」写成「小文 / 小闻 / 小吻」，匹配时会按常见同音写法放宽，也可以在设置里自己加词。
- **不会自己听见自己**。面板打开或正在录音时，监听自动让出麦克风（否则 AI 的回答会被当成唤醒词，反复触发）。
- **有限流**。开着电视或开会时人声不断，1 分钟内触发超过 12 次会自动歇 5 分钟，避免默默烧掉配额。
- **常驻开麦的代价**：会一直显示麦克风占用，CPU 有一点常驻开销。介意的话关掉开关即可，双击悬浮球或 `Alt+Space` 照常能用。

## 打包发布

```bash
# 生成安装包（NSIS，可选安装目录）
npm run dist

# 只生成免安装目录版
npm run dist:dir
```

产物在 `release-v1.5.0/` 目录：

- `XiaoWen-Setup-1.5.0.exe` —— 编译好的 Windows x64 安装包（**发版要发的就是这个**）
- `latest.yml` —— 自动更新的清单，必须和 exe 一起上传
- `XiaoWen-Setup-1.5.0.exe.blockmap` —— 增量更新用
- `XiaoWen-Setup-1.5.0.exe.sha256.txt` —— 校验和

> 产物名固定成 ASCII（`artifactName` 配的 `XiaoWen-Setup-${version}.${ext}`）。
> 之前用中文名时，electron-builder 会把它在 `latest.yml` 里悄悄写成拼音名，
> 导致 `latest.yml` 指向的资产不存在、老用户更新 404 —— 这个坑已经堵上，别再改回中文名。

### 发一个新版本（推荐：推 tag 自动出包）

**发版 = 发编译产物，不是发源码。** 只推源码 / 只建 tag，老用户的自动更新是拉不到的，
必须把 `.exe` 和 `latest.yml` 传到 Release 上。仓库已配置好 GitHub Actions，推 tag 就自动完成：

```bash
# 1. 改版本号（version + 打包输出目录一起改，避免对不上）
npm run version:bump 1.9.0
#    再补 CHANGELOG.md，跑测试
npm test                       # 全量白盒单测，纯 Node，跑完约 12 秒
# 也可以单跑（下面这些都已经在 npm test 里）：
#            test:context / test:hotkey / test:reload / test:config / test:meeting /
#            test:entry / test:clip / test:memory / test:session / test:schedule /
#            test:schedule-event / test:proactive / test:orch / test:llm / test:pet /
#            test:tray / test:wake / test:tools / test:capture / test:updater / test:packed-deps
# 另外还有个需要真实桌面的（不在默认流程里）：test:pet-top
#
# 配置相关的两条（都进 npm test）：
#   test:reload   配置热更新「改了什么要重载什么」的判据
#   test:config   配置文件读写：坏文件逐字节备份 / 读不动就拒绝写 / 设置界面写的键必须都在 DEFAULT_CONFIG 里
#
# 打包内容校验（防「装完之后才发现少东西」）：
#   check:deps         已进 npm test —— 源码里裸 require 的模块必须声明在 dependencies 里
#   test:packed-deps   已进 npm test —— 上面那套校验的自测（合成 asar，秒级）。
#                      它同时也守着「这份自测自己不许依赖构建产物」：清单里 dist/*.html
#                      这类产物项不要求此刻存在，而是现算 vite 会不会产出它
#                      （此前这里要求「磁盘上先有 dist/」，本地绿、CI 干净检出红 ——
#                        v1.12.0 / v1.13.0 因此连着两次没发出安装包）
#   test:packed        手动跑：先 npm run dist:dir，再校验真实的 app.asar（见下）

# 1.5 打包完先验一遍再发布（这一步能拦住「托盘没图标 / 语音识别挂 / 依赖没进包」）
npm run dist:dir && npm run test:packed

# 2. 提交，然后推一个 vX.Y.Z 格式的 tag
git commit -am "release: v1.9.0"
git push origin main
git tag -a v1.9.0 -m "v1.9.0"
git push origin v1.9.0
```

`.github/workflows/release.yml` 会在 windows runner 上自动：

1. `npm ci` → 跑回归测试（纯 Node 白盒单测）→ `npm run build:renderer`
2. `electron-builder --win nsis` 编译安装包
3. 把 **`.exe` + `.exe.sha256.txt` + `latest.yml` + `.blockmap`** 挂到该 tag 的 Release 上

也可以在 Actions 页面手动触发（填一个已存在的 tag 重跑发布）。

### 手动发版 / 补挂产物（没网、不想等 CI，或忘了带包）

```bash
npm run dist                 # 编译安装包（不会自动发布）
npm run release:upload v1.5.0
```

`release:upload` 会自动：

1. 在 `release-*` 目录里找出 exe / latest.yml / blockmap / sha256
2. 该 tag 没有 Release 就按 CHANGELOG 生成一个（非草稿）
3. 逐个上传（同名资产先删后传，可反复执行）

凭据顺序：环境变量 `GH_TOKEN` → git 里已保存的 github.com 登录态。脚本里不存任何密钥。

- 版本号必须比用户装的高，且 tag 名形如 `v1.5.0`
- 老用户启动后 8 秒会自己检查到，后台下完问一句要不要重启
- 没上传 `latest.yml` 的话只会显示「发布源里还没有可用的更新包」，不影响正常使用
- ⚠️ 只推 tag（发纯源码）时，Release 里没有编译产物，等于这次发版对老用户「没发生」

## 常见问题

**Q：配置时「测试连接」报 `HTTP 400 · Non-stream chat request is currently not supported`？**
v1.5.1 起所有对话请求默认走流式（`stream: true`），不会再出现这个错误。
遇到的话升级到 v1.5.1 及以后即可；旧版本可以先点「跳过」，进设置后再改。

**Q：双击了没反应 / 托盘图标不见了？**
Windows 默认会折叠托盘图标，点任务栏的「^」展开，把小问助手拖出来固定。

**Q：程序打不开（双击一闪而过）？**
v1.0.2 已处理两类常见原因：GPU 进程崩溃、以及上次被强制结束留下的单实例锁
导致新进程误以为「已有实例在运行」而静默退出。正常情况下不会再出现。
如果仍打不开，试试：

1. 先彻底退出旧进程：任务管理器里结束所有 `小问助手.exe`，再重新双击
2. 检查托盘区（点任务栏的「^」）—— 可能程序已在运行，只是窗口被隐藏了
3. 右键 `小问助手.exe` → 以管理员身份运行
4. 检查是否被杀毒软件拦截（把程序加入白名单）
5. 删掉配置目录后重试：`%APPDATA%\xiaowen-assistant`

**Q：提示 `HTTP 401 · Incorrect API key provided`？**
说明服务端没收到正确的 Key。按顺序排查：

1. **确认 Key 完整**：到设置里重新粘贴一次完整 Key。注意不要复制到
   打码后的文本（形如 `sk-abc***wxyz`），带 `***` 的一定是无效的，
   程序也会直接拦下并提示。
2. **确认 Key 没过期/没被禁用**：登录服务商后台看 Key 状态与余额。
3. **确认 BaseURL 与 Key 匹配**：Key 是从哪家申请的，地址就要填哪家。
   比如 DeepSeek 的 Key 不能配 OpenAI 的地址。
4. **检查 BaseURL 格式**：多数服务商需要带 `/v1`
   （如 `https://api.openai.com/v1`），DeepSeek 则用
   `https://api.deepseek.com`。程序会自动去掉结尾多余的 `/`，
   也会自动识别你填了完整 `/chat/completions` 的情况。
5. 点设置里的「测试连接」，它会直接用当前填写的值发一次请求，
   比盲猜更快定位问题。

**Q：启动日志在哪？**
`%USERPROFILE%\.xiaowen\launch.log`。里面记录了渲染模式、单实例锁判定、
看门狗自检等关键信息，排查启动问题时先看它。

**Q：想启用硬件加速（追求更流畅）？**
用 `小问助手.exe --enable-gpu` 启动，或在设置里关闭「禁用硬件加速」后重启。
注意：部分显卡驱动异常的机器开启后可能无法启动。

**Q：语音识别没反应 / 提示失败？**

1. 打开设置 → 语音，点「测试语音识别」—— 这一步能准确区分问题：
   - 提示「Key 无效」→ 重新去控制台复制完整 Key（注意别复制成带 `***` 的打码文本）
   - 提示「无法连接」→ 检查网络或代理
   - 显示「连接成功」但说话没反应 → 检查麦克风权限与被占用情况
2. 确认麦克风权限：Windows 设置 → 隐私和安全性 → 麦克风
3. 确认麦克风没有被其他程序独占（如腾讯会议、钉钉）
4. 也可在设置里把「识别方式」切到「系统内置」作为备选（依赖 Google 服务，国内通常不可用）

**Q：回答没有朗读？**
设置里确认「朗读 AI 回答」开着，并点「试听」确认系统语音引擎正常。

**Q：想换悬浮球位置？**
直接拖到想要的位置，松手会自动贴边。

**Q：API 费用怎么算？**
按服务商的 token 计费，小问本身不收费。设置里可调「上下文轮数」控制 token 消耗，调小更省钱。

**Q：怎么完全退出？**
右键托盘图标 → 退出小问助手。关闭面板窗口只是隐藏，程序仍在托盘常驻。

## 渲染模式说明（重要）

程序内置了**保守的渲染策略 + 自动降级**，以优先保证「能打开」：

| 档位 | 触发条件 | 效果 |
|---|---|---|
| 软件渲染（默认） | Windows 首次启动 | 关闭硬件加速，兼容性最好 |
| 硬件加速 | 加 `--enable-gpu` 或在设置里关闭开关 | 流畅度更好 |
| 免沙箱 | Windows 上始终启用 | 规避系统/安全软件拦截子进程 |
| 崩溃自愈 | 上次启动未走完初始化 | 下次自动降级并重试 |

启动日志会打印当前档位（`[gpu]` / `[sandbox]` 前缀），排查问题时可以参考。

### 手改 config.json 写坏了会怎样

`config.json` 是可以手改的（`config.example.json` 就是给你照抄的模板），所以它写坏了一定会发生。
不会静默丢配置：

- 文件**解析不了**（少个逗号、多个括号）或**顶层不是对象**（`[...]` / `"x"` / `null`）时，
  程序会先把原始内容**逐字节**备份成 `config.json.bad-<时间戳>-<指纹>`，再按默认配置运行，
  并弹一条系统通知 + 在设置页顶部挂一条横幅告诉你备份文件名。同一份坏内容只会备份一次。
- 备份写下去之后才允许继续保存设置 —— 不然界面会变成「点了保存但没生效」，更难查。
- **备份路径**：`%APPDATA%\xiaowen-assistant\config.json.bad-*`。把里面能救的部分填回新的 `config.json` 即可恢复。
- 空文件（或只有空白）**不算损坏**：那是写入中断的典型残留，没有内容可备份，直接按默认值走。
  （写盘本身改成「临时文件 + 原子替换」，正常情况下不会再产生这种残留。）
- 文件**读不动**（被别的程序锁着 / 权限不足）时**拒绝写入**：连读都没读到，无从判断写下去会毁掉什么。
  这时设置页会明说「本次运行不会写入任何设置」。
- 配置里出现**不认识的键**（`hotKey`、`apiKeyy` 这类拼错）时会在设置页顶部点名 —— 这些键不会生效，
  但以前的提示只写进日志，界面上完全看不出来。

## 技术栈

- **Electron 32** — 桌面容器
- **原生 JS + Vite 5** — 无框架依赖，启动快、体积小
- **Function Calling** — Agent 工具循环（OpenAI 协议）
- **MCP (Model Context Protocol)** — 外部工具生态
- **阿里云百炼** — paraformer-realtime 识别 + CosyVoice 合成（同一 WebSocket 端点）
- **Web Speech API** — 系统语音合成（离线）
- **OpenAI 兼容接口** — 一套代码支持多家大模型
